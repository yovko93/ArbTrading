## Findings and corrections

- **Diagnostic recovery reproduced.** Two new tests failed against the reviewed code: live sequence 20 caused history 1–19 to be skipped, and live sequence 1 after an old instance reached 500 inherited its cursor. `DesktopDiagnostics` now separates the completed REST history cursor from the highest live sequence, scopes both to workspace and backend instance, and clears old-instance entries on restart. Overlap, out-of-order arrivals, repeated refreshes, workspace changes, bounded retention, and explicit gap notices have deterministic tests. No durable event system was added.
- **Private-state invalidation confirmed and strengthened.** Before the patch, access denial cleared the primary snapshot but retained backend diagnostics, and a callback already queued for the UI could apply after the denial. Confirmed authentication or authorization failure now clears private snapshot fields, backend events, deduplication and recovery state. The realtime generation is invalidated before UI cleanup; the generation and scope are checked again inside queued UI work. Delayed save and snapshot responses from an old identity are ignored. A controllable queued dispatcher test and a real invalid-credential process test cover these paths. Desktop-local diagnostics and appearance preferences remain.
- **Process existence corrected.** The old observation path could report NotRunning when HTTP and TCP failed even if protected metadata identified a live managed process. A small process-inspector boundary now checks PID, start time, and executable path. A known live process with an unavailable endpoint or an unverified identity is Unknown and cannot enable Start. An exited managed process may allow Start; an occupied external endpoint blocks it. Tests use deterministic process evidence; the existing real launch test still uses the OS inspector.
- **Graceful Stop races corrected.** Stop now acquires and verifies the intended OS process handle before the authenticated request. It waits on that same handle, so immediate exit cannot turn into a failed PID lookup and PID reuse cannot redirect observation. A lost acknowledgment is reported as confirmed exit only when that captured handle independently confirms it; a live process or timeout stays unconfirmed. Instance-scoped metadata cleanup leaves replacement metadata untouched. Deterministic tests cover fast exit, timeout, PID/identity mismatch, both lost-acknowledgment outcomes, and replacement metadata.
- **Stop intent scoped to an instance.** Refresh no longer clears an old Stop request before a replacement is validated. After A stops, a separately started B can be authenticated, subscribed, and synchronized by Refresh; only then is A's stop intent cleared. A later B disconnect follows normal automatic retry. The updated isolated Kestrel/WebSocket process test exercises A → B → C, including B's unexpected disconnect. Refresh and reconnect do not launch or stop an OS process.

Changed production files: `DesktopDiagnostics.cs` (history scope/cursor and private clearing), `RealtimeSession.cs` (queued-UI guards and instance-scoped Stop), `MainViewModel.cs` (complete private-state clearing and delayed-result rejection), and `LocalBackendController.cs` (process evidence and stable shutdown handle).
