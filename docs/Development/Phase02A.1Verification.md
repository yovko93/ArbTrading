## Findings and correction

Focused raw-response tests first reproduced the reviewed errors: `active`, `initialized`, and `inactive` Kalshi REST statuses were Unknown, `closed` was incorrectly Finalized, and boolean/number/object/array continuation fields ended paging as if successful. Tests then passed after the parser change. [Kalshi's lifecycle contract](https://docs.kalshi.com/getting_started/market_lifecycle), [Get Markets contract](https://docs.kalshi.com/api-reference/market/get-markets), and [changelog](https://docs.kalshi.com/changelog) were checked on this date. The synthetic fixtures follow the official REST response vocabulary; they are not live captures.

Kalshi now requests four distinct buckets: `unopened`, `open`, `paused`, `closed`. Its response mapping is `initialized` → Upcoming, `active` → Open, `inactive` → Paused, `closed` → Closed, `determined` → Determined, `disputed` → Disputed, `amended` → Amended, and `finalized` → Finalized. Unknown native values remain Unknown with a warning. The source's native status text remains intact. Polymarket `closed=true` is now Closed rather than Finalized. Neither close timestamps nor trading closure imply settlement. Historical finalized markets are not backfilled. Complete is bounded to the four current Kalshi buckets or Polymarket `closed=false` traversal, subject to request/time budgets and valid pagination; it is not an atomic upstream snapshot.

The last-complete query now matches the exact declared scope. A pre-correction three-bucket Kalshi Complete run is retained in history but cannot set current full-coverage metadata. Backend startup performs an idempotent SQLite correction of cached normalized statuses when stored native status provides evidence. It does not change `RetrievedAt`, `FirstRetrievedAt`, run timestamps, identity, or settings. Ambiguous native data stays Unknown. Applied migrations were not edited.

Both adapters validate the object envelope, market array, and continuation type. Kalshi requires its cursor field and treats only an empty string as terminal; Polymarket accepts a string, null, or omission with explicit `has_more=false`. Unsupported types fail. Opaque nonempty cursors, exact external ID text, page-size independence, cycle detection, incremental storage, and partial outcomes remain. Production-parser/coordinator tests for both exchanges verify that a valid first page survives an invalid or repeated second cursor, the run is Failed, and last-complete metadata does not advance.

Market Explorer now serializes catalog read batches. Notifications coalesce into one pending read; filter and lifecycle changes cancel/supersede earlier reads. Page, status, and detail requests receive cancellation tokens. Access invalidation, deactivation, and disposal reset Loading and prevent late responses from restoring stale state. Existing workspace edits, backend-owned sync jobs, and one-attempt Sync/Cancel mutations remain unchanged. Deterministic delayed-response tests cover burst bounds, query replacement, cancellation, authorization loss, deactivation, and late detail.

`PublicMarketSources.cs` distinguishes supported .NET secure-connection errors from ordinary transport failures, without asserting that every TLS problem is an untrusted root. Confirmed secure-connection errors do not enter the ordinary retry loop. The exception chain is retained for sanitized diagnostic classification; the backend logs only the exchange and error code. Local workspace authentication is unaffected.
