# Execution

Phase 04F extends `PaperAutomationPolicy` with explicit `LargestAdmissibleGridQuantity`, while retaining FixedQuantity and its v1 canonical hashes. `PaperQuantityGrid` constructs exact decimal Min + N × Step (≤ Max), descending, at most 256 points; step means a simulation grid, not exchange lot size. `PaperSizer` checks each quantity until the first approval without assuming monotonic admission. The backend supplies exact L2/fee/planner/risk/automation evaluation against captured immutable inputs. A 512-evaluation cycle budget defers unstarted searches; no financial writer resizes after selection.

Compact v2 sizing proofs bind the grid, selected exact plan, rejection counts, risk/automation revisions, financial revision and session debits to a canonical SHA-256 digest. Market stamps exclude mutable cash/exposure/session balances, so financial changes do not manufacture new triggers. Existing fixed v1 proofs and request IDs remain supported. Realtime quality, economics, deduplication, counts, cooldowns and per-bucket gross entry debit remain enforced. Backend owns memory-only armed permits; Infrastructure repeats admission and kill checks in the existing writer transaction. This project acquires no market data and implements no scheduler, persistence, optimizer, AI/Kelly sizing, live trading, settlement or SELL path.

Phase 04D adds pure `PaperRiskEvaluator`, immutable `PaperRiskLimits`/`PaperRiskProfile`, accounting-only `CurrentPaperRiskState`, and typed decisions with exact violations/headroom. It evaluates an already validated `PaperPlan`; it does not duplicate relationship, fee or depth algorithms. Initial cash is the stable denominator for each exchange/currency. Infrastructure reads accounting state and re-evaluates under the serialized financial writer transaction. There are no implicit active defaults, marks used for admission, or automatic quantity suggestions.

Active Phase 04A pure paper-execution boundary. `PaperPlanner` projects existing paired-depth and fee evaluations into native-level snapshot fills. `PaperAccounting` provides checked decimal cash and position arithmetic. Infrastructure persists the ledger; Backend coordinates explicit authenticated preview/confirmation. Execution has no transports, credentials, EF/SQLite or WPF dependencies.

Phase 04B adds pure `PaperSettlement` rules for explicit ManualScenario binary 1/0 payouts, position P&L and partial/full execution economics. Captured deterministic complementary execution proof rejects contradictory payouts. Infrastructure coordinates atomic settlement and reconciliation; Backend exposes owner-only preview/confirm; no current market-data or fee source is required.

Phase 04C adds pure `PaperValuation`: read-only executable SELL-depth diagnostics over held paper inventory. The existing `ExecutableDepth` supplies actual consumed native bid levels and exact decimal proceeds; `FeeMath` evaluates each consumed level using current cached fee assumptions. Incomplete depth never invents a full mark. Unresolved exit fees preserve gross analytics but leave fee-adjusted values null. Historical entry costs and settlement facts remain immutable.

Only paper simulation and read-only analytics exist. No automatic exchange-result ingestion, real orders, signing, private balances/positions, transfers, redemption, paper SELL/close execution, market impact or capital allocation are implemented. Unsupported void/scalar/negative-risk/complex payouts fail closed. Paper atomicity does not establish live cross-exchange atomicity. See [architecture](../../docs/Architecture/PaperExecution.md).
